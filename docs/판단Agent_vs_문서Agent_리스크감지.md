# 판단 Agent vs 문서 Agent 리스크 감지 — 경계 정의

> 멘토 피드백 반영: 두 기능의 입력/목적/출력 차이를 명확히 정리

---

## 한눈에 보기

| 구분 | 판단 Agent (경은) | 문서 Agent 리스크 감지 (승언) |
|------|-------------------|-------------------------------|
| **입력** | 사용자의 직접 질문 ("연차 가능한가요?") | 업로드된 문서 자체 (계약서, 보고서 등) |
| **목적** | 규정 근거 기반 **Yes/No 판단** | 문서 내 **위험 요소 탐지** (불리한 조항 등) |
| **RAG 대상** | 사내 규정 문서 (Qdrant `documents` 컬렉션) | 업로드 문서 + 관련 법/규정 |
| **출력** | 판단 결과 + confidence + 근거 조항 | 리스크 항목 리스트 + 심각도 |
| **트리거** | Intent = `judgment` | Intent = `doc_search` (리스크 감지 서브태스크) |
| **LLM 프롬프트** | `JUDGMENT_SYSTEM_PROMPT` | `RISK_DETECTION_SYSTEM_PROMPT` |

---

## 1. 판단 Agent (경은 담당)

### 흐름
```
사용자 질문
  → Intent 분류 (judgment)
  → RAG 하이브리드 검색 (BM25 + Vector → RRF, top_k=7)
  → 규정 그룹핑 (다중 규정 교차 분석)
  → LLM 판단 요청
  → 3중 보조 장치 적용:
    1) 규정 키워드 매칭 (환각 탐지)
    2) 조항 존재 여부 검증
    3) 카테고리 제한 (yes/no/conditional/no_regulation)
  → confidence 보정 (LLM 60% + RAG 25% + 커버리지 15% - 감점)
  → 일관성 모니터링 (캐시 비교)
  → 판단 결과 반환
```

### 응답 형식
```json
{
  "type": "judgment",
  "result": "yes | no | conditional | no_regulation",
  "confidence": 0.85,
  "reasoning": "판단 근거 설명",
  "regulations": [
    {"article": "제8조", "relevance": "높음", "content": "관련 내용 요약"}
  ],
  "cross_references": [
    {"articles": ["제8조", "제12조"], "relationship": "보완", "detail": "관계 설명"}
  ],
  "conditions": "조건부일 때 조건 설명",
  "alternatives": ["대안1"],
  "regulation_groups": ["제3장 근로시간 및 휴가"],
  "article_validations": [{"article": "제8조", "exists": true}],
  "warnings": []
}
```

### 핵심 특징
- **질문 기반**: 사용자가 "~할 수 있나요?"를 질문
- **규정 근거 필수**: RAG 검색 결과에 근거 조항이 없으면 `no_regulation`
- **신뢰도 보정**: LLM 과신 방지 (RAG 점수가 낮으면 confidence 하향)
- **환각 탐지**: LLM이 존재하지 않는 조항을 인용하면 감점 + 경고

## 2. 문서 Agent 리스크 감지 (승언 담당)

### 흐름
```
사용자가 문서 업로드
  → 텍스트 추출 (PDF/DOCX → 텍스트)
  → 문서 내용 분석
  → 관련 규정/법률 RAG 검색 (필요시)
  → LLM에 리스크 분석 요청
  → 리스크 항목 + 심각도 반환
```

### 응답 형식
```json
{
  "type": "doc_search",
  "risk_level": "높음 | 중간 | 낮음 | 없음",
  "risks": [
    {
      "description": "계약 해지 시 위약금 조항이 과도합니다",
      "regulation": "민법 제398조 (손해배상액의 예정)",
      "level": "높음",
      "recommendation": "위약금 상한을 계약금의 20% 이내로 조정 권장"
    }
  ]
}
```

### 핵심 특징
- **문서 기반**: 사용자가 문서를 업로드하면 자동 분석
- **위험 요소 탐지**: 불리한 조항, 규정 위반 가능성, 빠진 필수 조항 등
- **대조 분석**: 업로드 문서 내용을 관련 법/규정과 대조
- **다수 항목**: 여러 리스크를 항목별로 나열 (vs 판단 Agent는 단일 Yes/No)

## 3. 경계가 겹칠 수 있는 시나리오

| 시나리오 | 어디로 라우팅? | 이유 |
|----------|---------------|------|
| "이 계약서에 문제 있어?" | **문서 Agent** (리스크 감지) | 문서 자체를 분석하는 것 |
| "계약서에 위약금 30%가 합법인가요?" | **판단 Agent** | 특정 조항에 대한 규정 기반 Yes/No |
| "우리 회사 재택근무 가능한가요?" | **판단 Agent** | 사내 규정 기반 판단 |
| "이 보고서에서 규정 위반 요소 찾아줘" | **문서 Agent** (리스크 감지) | 문서 전체 스캔 |

## 4. 기술적 차이 요약

| 항목 | 판단 Agent | 문서 Agent 리스크 감지 |
|------|-----------|----------------------|
| **파일** | `ai/agents/judgment_agent.py` | `ai/agents/document_agent.py` |
| **프롬프트** | `JUDGMENT_SYSTEM_PROMPT` | `RISK_DETECTION_SYSTEM_PROMPT` |
| **RAG 쿼리 소스** | 사용자 질문 텍스트 | 업로드 문서에서 추출한 텍스트 |
| **confidence 보정** | O (3중 보조 장치) | X (리스크 자체에 level 부여) |
| **캐싱/일관성** | O (동일 쿼리 모니터링) | X (문서마다 다르므로 불필요) |
| **스트리밍** | O (`judgment_agent_stream`) | 향후 구현 예정 |

## 5. 발표 포인트

> "판단 Agent는 **사용자 질문**에 대해 규정 근거 기반으로 **Yes/No를 판단**하는 역할이고,
> 문서 Agent 리스크 감지는 **업로드된 문서 자체**를 스캔하여 **위험 요소를 탐지**하는 역할입니다.
>
> 두 기능 모두 RAG를 사용하지만, 판단 Agent는 사내 규정만 검색하고,
> 리스크 감지는 업로드 문서와 관련 법/규정을 함께 대조합니다.
>
> 판단 Agent에는 **3중 보조 장치**(환각 탐지 + 조항 검증 + 카테고리 제한)를 두어
> 단순히 LLM에게 맡기는 것이 아니라 **RAG 점수 기반 보정 + 규정 존재 여부 검증**으로
> 신뢰도를 보장합니다."
