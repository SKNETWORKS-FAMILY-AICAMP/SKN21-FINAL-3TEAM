## 1. v2_generate (문서 생성) — 프롬프트 수정 필요

### 요구사항
- 사용자가 올린 양식(DOCX)대로 회의록/제안서/보고서 생성
- 새 양식 추가되어도 sLLM 재학습 없이 대응 (동적 필드 방식)

### 현재 프롬프트 (문제 있음)
```
당신은 기업 문서 작성 전문가입니다.
사용자가 제공하는 [필드 명세]에 따라 문서 내용을 JSON으로 생성하세요.

규칙:
- [필드 명세]에 정의된 필드만 JSON 키로 사용하세요.
- 각 필드의 설명을 참고하여 적절한 값을 생성하세요.
- 입력 내용에 해당 정보가 없으면 빈 문자열 또는 빈 배열로 두세요.
- 배열 필드는 반드시 JSON 배열 형태로 출력하세요.
- 반드시 JSON만 출력하세요. 설명 텍스트나 마크다운을 포함하지 마세요.
```

### 문제점
- **"적절한 값을 생성"이 모호** — 모델이 필드 설명을 그대로 값으로 복사할 위험
- 프로덕션 고정 프롬프트에 있던 "실제 내용으로 작성", "지침 문장을 값으로 출력 금지" 규칙이 빠짐
- 예시:
  ```json
  // 나쁜 예 — 필드 설명 복사
  {"summary": "회의에서 논의된 주요 내용을 파트별로 3~5문장으로 요약"}

  // 좋은 예 — 실제 내용 생성
  {"summary": "AWS 인프라 도입이 결정되었으며, 3월 말 MVP 완성을 목표로..."}
  ```

### 개선안
```
당신은 기업 문서 작성 전문가입니다.
사용자가 제공하는 [필드 명세]에 따라 문서 내용을 JSON으로 생성하세요.

규칙:
- [필드 명세]에 정의된 필드만 JSON 키로 사용하세요.
- 각 필드의 설명을 참고하여, 입력 내용을 바탕으로 실제 내용을 작성하세요.
- 필드 설명이나 지침 문장을 그대로 값으로 출력하지 마세요.
- 입력 내용에 해당 정보가 없으면 빈 문자열 또는 빈 배열로 두세요.
- 배열 필드는 반드시 JSON 배열 형태로 출력하세요.
- 반드시 JSON만 출력하세요. 설명 텍스트나 마크다운을 포함하지 마세요.
```

## 2. v2_summary (문서 요약) — 프롬프트 수정 필요

### 요구사항
- 지정한 양식대로 요약 (핵심요약 + 주요포인트 + 키워드)

### 현재 프롬프트 (문제 있음)
```
당신은 기업 문서 요약 전문가입니다.
주어진 문서를 분석하여 핵심 내용을 정리합니다.

규칙:
- 문서의 핵심 요약을 먼저 2-3문장으로 작성하세요.
- 주요 포인트를 마크다운 불릿 리스트로 정리하세요.
- 중요 키워드를 별도로 나열하세요.
- 원문에 없는 내용을 추가하지 마세요.
- 한국어로 답변하세요.
```

### 문제점
- **"## 주요 포인트", "## 키워드" 헤딩명이 프롬프트에 없음** — 학습 데이터에는 있는데
- **포인트 개수 미지정** — 3~5개? 무제한?
- **키워드 개수 미지정** — 3개? 10개?
- **키워드 구분자 미지정** — 학습 데이터는 쉼표 구분인데 프롬프트에 안 써있음
- 프롬프트와 학습 데이터 사이에 "암묵적 약속"이 있음 → sLLM은 이걸 못 따라감

### 실제 학습 데이터 출력 형식
```markdown
핵심 요약 2~3문장

## 주요 포인트
- 포인트 1
- 포인트 2
- 포인트 3

## 키워드
키워드1, 키워드2, 키워드3, 키워드4, 키워드5
```

### 개선안
```
당신은 기업 문서 요약 전문가입니다.
주어진 문서를 분석하여 핵심 내용을 정리합니다.

반드시 아래 형식으로 출력하세요:

1. 핵심 요약 2~3문장
2. 빈 줄
3. ## 주요 포인트
4. 불릿(-)으로 3~5개 포인트
5. 빈 줄
6. ## 키워드
7. 핵심 키워드 3~7개를 쉼표로 구분

규칙:
- 원문에 없는 내용을 추가하지 마세요.
- 키워드는 명사/명사구만 사용하세요.
- 한국어로 답변하세요.
```
**변경**: 출력 형식 단계별 명시, 포인트 개수(3~5), 키워드 개수(3~7), 쉼표 구분 명시

## 3. v2_qa (문서 QA) — 프롬프트 + 데이터 모두 수정 필요

### 요구사항
- 문서 기반 질의응답 (RAG 컨텍스트 + 질문 → 답변)
- 어떻게 해야 할지 고민 중

### 현재 프롬프트
```
당신은 기업 문서 기반 질의응답 전문가입니다.
주어진 문서 내용을 근거로 사용자의 질문에 정확하게 답변합니다.

결과는 반드시 아래 JSON 형식으로만 응답하세요:
{
    "answer": "질문에 대한 답변",
    "citations": [
        {"source": "문서명/출처", "content": "인용 내용", "relevance": "높음|중간|낮음"}
    ],
    "confidence": 0.0~1.0
}

규칙:
- 반드시 제공된 문서 내용만을 근거로 답변하세요.
- 답변의 근거가 되는 문서 내용을 citations에 포함하세요.
- 문서에서 답을 찾을 수 없으면 confidence를 낮게 설정하고 솔직히 답하세요.
- 추측이나 외부 지식으로 답변을 보충하지 마세요.
- JSON 외의 텍스트를 포함하지 마세요.
```

### 데이터 문제 (심각)
| 문제 | 현황 | 영향 |
|------|------|------|
| confidence | 0.9, 0.95 딱 2종류 | 모델이 항상 0.9/0.95만 출력 |
| relevance | 전부 "높음" | 모델이 항상 "높음"만 출력 |
| citations 수 | 전부 1개 | 모델이 항상 1개만 출력 |

- AI Hub 600건 + 합성 스크립트(`synthesize_qa.py`) 모두 같은 문제
- `build_training_sample` 함수에서 하드코딩한 게 원인

### 근본적 고민: sLLM이 진짜 해야 하는 것 vs 안 해도 되는 것

```
sLLM이 잘해야 하는 것:
  ✅ answer — 문서 기반 정확한 답변 (핵심)
  ✅ citations.content — 근거 인용 (핵심)

sLLM이 굳이 안 해도 되는 것:
  ❓ confidence — 백엔드에서 계산 가능 (RAG score, 토큰 확률)
  ❓ relevance — RAG reranker(bge-reranker)가 이미 판단
  ❓ citations.source — 백엔드가 이미 알고 있음 (RAG 검색 결과 메타데이터)
```

### 선택지 3가지

**A. 현행 유지 (JSON 전체) + 데이터 다양성 보완** ← 추천
```json
{"answer": "...", "citations": [...], "confidence": 0.85}
```
- 장점: 구조 변경 없음, 프로덕션 코드 수정 최소
- 단점: 8B 모델이 confidence/relevance를 정확히 판단하기 어려울 수 있음

**B. 간소화 — answer + citation_text만 출력**
```json
{"answer": "답변", "citation_text": "근거가 되는 원문 인용"}
```
- 장점: sLLM 학습 부담 줄어듦, 핵심에 집중
- 단점: confidence/source는 백엔드에서 별도 처리 필요, 프로덕션 코드 변경 필요

**C. 자연어 출력 — JSON 포기**
```
답변 텍스트 (근거: "인용 내용")
```
- 장점: sLLM이 가장 잘하는 형태, 스트리밍에 유리
- 단점: 파싱 필요, 구조화 어려움, 프로덕션 코드 대폭 변경

### 개선안 (A 선택 시)
```
당신은 기업 문서 기반 질의응답 전문가입니다.
주어진 문서 내용을 근거로 사용자의 질문에 정확하게 답변합니다.

결과는 반드시 아래 JSON 형식으로만 응답하세요:
{
    "answer": "질문에 대한 답변",
    "citations": [
        {"source": "문서명/출처", "content": "인용 내용", "relevance": "높음|중간|낮음"}
    ],
    "confidence": 0.0~1.0
}

규칙:
- 반드시 제공된 문서 내용만을 근거로 답변하세요.
- 답변의 근거가 되는 문서 내용을 citations에 포함하세요.
- 근거가 여러 곳이면 citations를 2~3개까지 포함하세요.
- relevance는 답변과의 관련도에 따라 높음/중간/낮음으로 구분하세요.
- confidence는 근거의 명확성에 따라 조절하세요:
  - 명확한 답변: 0.8~1.0
  - 추론 포함: 0.5~0.8
  - 근거 부족: 0.3 이하
- 문서에서 답을 찾을 수 없으면 confidence를 낮게 설정하고 솔직히 답하세요.
- 추측이나 외부 지식으로 답변을 보충하지 마세요.
- JSON 외의 텍스트를 포함하지 마세요.
```
**변경**: citations 복수 허용, relevance 판단 기준, confidence 구간 가이드 추가

### 합성 스크립트 수정 필요 (`synthesize_qa.py`)
`build_training_sample` 함수에서:
```python
# 수정 전 (하드코딩)
"relevance": "높음"
"confidence": 0.95 if len(answer) > 50 else 0.90

# 수정 후 (다양성)
"relevance": random.choices(["높음","중간","낮음"], weights=[0.6,0.3,0.1])[0]
"confidence": round(random.uniform(0.7, 0.98), 2)
# + citations 2~3개 케이스 추가
# + 부정 예시 비율 5% → 10~15%로 확대
```
