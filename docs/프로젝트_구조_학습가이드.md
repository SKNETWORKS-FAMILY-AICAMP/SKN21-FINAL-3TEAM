## 3. 사용자가 "회의록 작성해줘" 라고 채팅하면 벌어지는 일

### Step 1: Frontend (React)

```
ChatPage.jsx
  -> useChat.js (sendMessage 호출)
    -> useSSE.js (SSE 스트리밍 연결)
      -> POST /api/v1/chat/stream
         Body: { message: "회의록 작성해줘", session_id: "abc123" }
```

**관련 파일:**
- `frontend/src/pages/ChatPage.jsx` - 채팅 페이지 전체
- `frontend/src/hooks/useChat.js` - 메시지 전송 로직 (30줄짜리 핵심)
- `frontend/src/hooks/useSSE.js` - 서버에서 실시간 응답 받는 로직
- `frontend/src/store/chatStore.js` - 채팅 세션/메시지 상태 관리

### Step 2: Backend (FastAPI)

```
chat.py (API 엔드포인트)
  -> chat_service.py (비즈니스 로직)
    -> AgentState 초기화 {
         user_input: "회의록 작성해줘",
         user_id: 123,
         chat_history: [...이전 대화...]
       }
    -> graph.invoke(state)  # LangGraph 실행!
```

**관련 파일:**
- `backend/app/api/v1/chat.py` - /chat/stream 엔드포인트
- `backend/app/services/chat_service.py` - AI 호출 + SSE 스트리밍
- `backend/app/api/v1/router.py` - 모든 API 경로 모음

### Step 3: AI (LangGraph) - 핵심!!

```
orchestrator.py (그래프 실행)
  |
  v
[1] classify_intent_v2 (의도 분류)
    "회의록 작성해줘" -> intent: "meeting_generate", confidence: 0.95
  |
  v
[2] route_by_intent (라우팅)
    meeting_generate -> document_agent로 보내!
  |
  v
[3] document_agent.py (문서 에이전트)
    meeting_generate 처리 -> 회의록 템플릿 + LLM 호출
  |
  v
[4] format_response (응답 정리)
    { type: "meeting_generate", message: "회의록이 생성되었습니다", content: "..." }
```

**관련 파일:**
- `ai/agents/orchestrator.py` - **전체 흐름의 뇌** (LangGraph 그래프 정의)
- `ai/agents/intent_classifier.py` - 의도 분류기 (BERT 모델)
- `ai/agents/state.py` - 모든 Agent가 공유하는 데이터 구조
- `ai/agents/document_agent.py` - 문서/회의록 처리 (승언 담당)
- `ai/agents/judgment_agent.py` - 규정 판단 처리 (경은 담당)
- `ai/agents/schedule_agent.py` - 일정 처리 (혜빈 담당)

### Step 4: 응답이 돌아오는 길

```
AI 결과 -> Backend (SSE 이벤트로 변환)
  -> intent 이벤트: { type: "intent", intent: "meeting_generate" }
  -> token 이벤트:  { type: "token", value: "회의록..." }  (글자 하나씩)
  -> result 이벤트: { type: "result", data: {...전체 결과...} }
  -> done 이벤트:   { type: "done" }

Frontend (useSSE.js가 이벤트 처리)
  -> intent 받으면: IntentBadge 표시 ("회의록 생성 중...")
  -> token 받으면:  StreamingMessage에 글자 추가
  -> result 받으면: MeetingSummaryCard 렌더링
  -> done 받으면:   스트리밍 종료
```

## 4. 7가지 Intent (의도) 와 담당 Agent

```
사용자 입력 -> Intent 분류 -> Agent 라우팅

| Intent           | Agent          | 담당 | 예시                         |
| ---------------- | -------------- | ---- | ---------------------------- |
| judgment         | judgment_agent | 경은 | "연차 3일 연속 사용 가능해?" |
| doc_search       | document_agent | 승언 | "출장비 관련 규정 찾아줘"    |
| doc_generate     | document_agent | 승언 | "주간 보고서 작성해줘"       |
| meeting_generate | document_agent | 승언 | "회의록 만들어줘"            |
| schedule_add     | schedule_agent | 혜빈 | "내일 2시 회의 잡아줘"       |
| schedule_view    | schedule_agent | 혜빈 | "이번 주 일정 보여줘"        |
| general          | (LLM 직접)     | -    | "오늘 날씨 어때?"            |
```

**document_agent가 3개 intent 처리** (doc_search, doc_generate, meeting_generate)

## 6. 핵심 개념 설명

### 6-1. LangGraph란?
- LangChain 팀이 만든 **Agent 워크플로우 프레임워크**
- "그래프"로 AI 처리 흐름을 정의함 (노드 = 함수, 엣지 = 조건)
- 우리 프로젝트: `orchestrator.py`에서 그래프를 만들고, 각 Agent를 노드로 연결

### 6-2. RAG (Retrieval-Augmented Generation)란?
- LLM이 모르는 **우리 회사 규정/문서**를 검색해서 답변에 활용하는 기술
- 흐름: 질문 -> 문서 검색(Qdrant) -> 검색 결과 + 질문을 LLM에 전달 -> 답변
- judgment_agent가 "연차 3일 연속 가능?" 물으면 -> 사내 규정 검색 -> 근거 기반 답변

### 6-3. SSE (Server-Sent Events)란?
- 서버가 **실시간으로** 데이터를 클라이언트에 보내는 기술
- ChatGPT처럼 글자가 하나씩 나오는 효과를 이렇게 구현
- 일반 HTTP: 요청 -> 응답 (한번에)
- SSE: 요청 -> 토큰1 -> 토큰2 -> ... -> 완료 (스트리밍)

### 6-4. Zustand란?
- React 상태 관리 라이브러리 (Redux 대체)
- `authStore.js`: 로그인한 유저 정보, JWT 토큰
- `chatStore.js`: 채팅 세션 목록, 현재 메시지들
- `uiStore.js`: 다크모드, 사이드바 열림/닫힘
- `googleStore.js`: Google 서비스 연결 상태

### 6-5. Google Services 구조
```
GoogleBaseService (공통 인증/토큰 로직)
    |
    +-- CalendarService (일정 + Meet 링크)
    +-- TasksService (할일)
    +-- GmailService (이메일)
    +-- SheetsService (스프레드시트)

    --> ScheduleService가 위 4개를 통합 관리
```

### 6-6. DB 11개 테이블
```
users              - 사용자 계정
documents          - 업로드된 문서
document_templates - 문서 템플릿 정의
regulations        - 사내 규정 (RAG 검색 대상)
meetings           - 회의 기록
action_items       - 회의에서 나온 할 일
schedules          - 일정
judgments          - AI 판단 결과 저장
chat_logs          - 채팅 이력
oauth_tokens       - Google OAuth 토큰 (AES 암호화)
google_sheet_trackers - Google Sheets 연동 추적
```

## 7. PM(지용)이 만진 파일과 역할

지용이 직접 작업한 핵심 파일 3개:

1. **`ai/agents/orchestrator.py`** - 전체 AI 흐름의 "뇌"
   - LangGraph 그래프 정의 (노드 추가, 엣지 연결)
   - Intent에 따라 어떤 Agent로 보낼지 결정 (route_by_intent)
   - 복잡한 질문 분해, 대명사 해석, 저신뢰도 시 명확화 요청

2. **`ai/agents/state.py`** - 모든 Agent의 "공용 메모장"
   - AgentState (TypedDict) 정의
   - 모든 Agent가 이 구조에 데이터를 읽고 씀
   - user_input, intent, confidence, agent_response 등 필드

3. **`ai/agents/intent_classifier.py`** - "무슨 말인지 파악하는 분류기"
   - BERT 모델로 7가지 의도 분류
   - 복잡한 질문 감지 (is_complex)
   - 대명사 감지 ("그거 해줘" -> 이전 대화 참조 필요)

## 8. 개발 전략: 왜 LLM API 먼저?

```
현재 (1~3단계)              나중에 (4단계)
+------------------+       +------------------+
| GPT/Claude API   |  -->  | vLLM (자체 모델)  |
| (외부 API 호출)   |       | (파인튜닝된 모델)  |
+------------------+       +------------------+
       |                          |
       v                          v
  동일한 Agent 코드 (바뀌지 않음!)
  factory.py에서 provider만 교체
```

- 먼저 외부 API로 **전체 기능을 완성**
- input/output 형태가 확정되면 -> 그 형태에 맞는 데이터 수집
- 수집한 데이터로 **파인튜닝** -> 자체 모델 교체
- `ai/llm/factory.py`에서 `LLM_PROVIDER` 환경변수만 바꾸면 끝

## 9. 면접 대비: "이 프로젝트 설명해보세요" 답변 예시

> "저희 프로젝트 '듀듀'는 **LangGraph 기반 멀티 에이전트 업무 자동화 시스템**입니다.
>
> 사용자가 자연어로 업무를 요청하면, **BERT 기반 Intent Classifier**가 7가지 의도(판단, 문서검색, 문서생성, 회의록, 일정추가, 일정조회, 일반)를 분류하고, **LangGraph Orchestrator**가 적절한 전문 Agent에게 라우팅합니다.
>
> 판단 Agent는 **RAG(Hybrid Search + Reranker)** 기반으로 사내 규정을 검색해서 근거 기반 답변을 하고, 문서 Agent는 4가지 템플릿(회의록/보고서/JD/제안서)으로 문서를 자동 생성하며, 일정 Agent는 **Google Calendar/Tasks/Gmail/Sheets**와 연동됩니다.
>
> 기술적으로는 FastAPI(SSE 스트리밍) + React(Zustand) + PostgreSQL 구조이며, LLM Provider Factory 패턴으로 현재 GPT/Claude API를 사용하되, 추후 **LoRA 파인튜닝한 sLLM으로 교체** 가능하도록 설계했습니다.
>
> 저는 PM으로서 전체 아키텍처 설계, Intent 분류기 개발, LangGraph Orchestrator 구현을 담당했습니다."

## 10. Frontend ↔ Backend JSON 통신 형식

### 누가 형식을 정하나?

`backend/app/schemas/` 폴더의 **Pydantic 스키마**가 "계약서" 역할.

| 스키마 파일          | 정의한 사람            | 역할                                |
| -------------------- | ---------------------- | ----------------------------------- |
| `chat.py`            | **지용 (PM, 팀원 A)**  | AI Agent 응답 구조, SSE 이벤트 형식 |
| `auth.py`            | 혜빈 (Backend, 팀원 D) | 로그인/회원가입                     |
| `document.py`        | 혜빈                   | 문서 CRUD                           |
| `meeting.py`         | 혜빈                   | 회의 CRUD                           |
| `schedule.py`        | 혜빈                   | 일정 CRUD                           |
| `google_services.py` | 혜빈                   | Google 연동                         |

> Pydantic이 형식 정의 + 자동 검증 + JSON↔Python 변환 + API 문서화(`/docs`)까지 해줌.
> 형식 안 맞으면 FastAPI가 자동으로 422 에러 반환.

### 통신 방식 2가지

```
일반 REST API:  Frontend --[JSON]--> Backend --[JSON]--> Frontend  (한번에 주고받기)
채팅 SSE:       Frontend --[JSON]--> Backend --[SSE 이벤트 여러개]--> Frontend  (실시간 스트리밍)
```

모든 요청에 JWT 토큰이 헤더에 자동으로 붙음: `Authorization: Bearer eyJhbGci...`

### 10-2. 채팅 SSE 스트리밍 (핵심!)

ChatGPT처럼 글자가 하나씩 나오는 방식. **채팅만 이 방식 사용.**

#### 요청 (Frontend → Backend)

```
POST /api/v1/chat/stream
{
  "message": "회의록 작성해줘",
  "session_id": "abc123",
  "source_page": "chatbot",
  "template_type": "meeting_minutes"
}
```

#### 응답 (Backend → Frontend, 이벤트가 순서대로 하나씩 날아옴)

```
① data: {"type": "intent", "intent": "meeting_generate", "confidence": 0.95, "agent_type": "document_agent"}

② data: {"type": "status", "value": "회의록 생성 중..."}

③ data: {"type": "token", "value": "회"}
④ data: {"type": "token", "value": "의"}
⑤ data: {"type": "token", "value": "록"}
   ... (글자 하나씩 스트리밍)

⑥ data: {"type": "result", "intent": "meeting_generate", "data": {
     "meeting_id": 7,
     "summary": "프로젝트 진행 상황 공유",
     "decisions": ["결정사항1", "결정사항2"],
     "action_items": [{"content": "API 개발", "assignee": "혜빈", "due_date": "2026-02-25"}],
     "preview": "## 회의록\n...",
     "download_url": "/api/v1/documents/15/download"
   }}

⑦ data: {"type": "done", "chat_log_id": 99}
```

#### 에러 발생 시

```
data: {"type": "error", "message": "서비스 일시 장애", "code": "AGENT_ERROR"}
```

#### 복합 질문 시 (추가 이벤트)

```
data: {"type": "multi_intent", "data": {"total": 2, "sub_queries": ["규정 검색해줘", "판단해줘"]}}
data: {"type": "sub_query_done", "data": {"step": 1, "total": 2, "intent": "doc_search", "query": "규정 검색해줘"}}
```

#### 저신뢰도 시 (명확화 요청)

```
data: {"type": "clarify_candidates", "data": {"candidates": ["일정 추가", "일정 조회", "회의록 생성"], "message": "어떤 작업을 원하시나요?"}}
```
