# 오케스트레이터 구조 설명

> `ai/agents/orchestrator.py` — LangGraph StateGraph 기반 Agent 라우팅

## 전체 흐름 (v2 — Smart Hybrid)

```
[사용자 입력]
     |
  classify_intent_v2        ← BERT 분류 + 지시어 감지
     |
     |-- 지시어?  --> resolve_context --> classify_intent_v2 (재분류)
     |
     |-- < 0.7?  --> clarify_with_candidates --> format_response --> END
     |
     +-- >= 0.7? --> Agent 실행 --> format_response --> END
```

## 3가지 분기 (route_by_complexity)

| # | 조건 | 라우팅 | 설명 |
|---|------|--------|------|
| 1 | 지시어 감지 ("그거 해줘") | `resolve_context` -> `classify_intent_v2` 재실행 | LLM이 대화이력 보고 명확한 문장으로 복원 후 재분류 |
| 2 | confidence < 0.7 | `clarify_with_candidates` | top-3 후보 버튼으로 사용자에게 제시 |
| 3 | confidence >= 0.7 | 해당 Agent 직행 | BERT fast path (단일 질문 처리) |

## Agent 매핑 (분기 3번)

| intent | 노드 | 담당 |
|--------|------|------|
| `general` | `general_response_node` | LLM 직접 응답 |
| `judgment` | `safe_judgment_agent` | 경은 |
| `doc_search` | `safe_document_agent` | 승언 |
| `doc_generate` | `safe_document_agent` | 승언 |
| `meeting_generate` | `safe_document_agent` | 승언 |
| `schedule_add` | `safe_schedule_agent` | 혜빈 |
| `schedule_view` | `safe_schedule_agent` | 혜빈 |

## 주요 노드 설명

### classify_intent_v2
- BERT 모델로 intent 분류 (7개 카테고리)
- confidence (softmax 확률) 산출
- 지시어 감지 (`is_context_dependent`) — 정규식 패턴 매칭

### resolve_context
- 지시어("그거", "아까", "위에 문서" 등) 감지 시 진입
- LLM이 최근 5턴(10개 메시지) 대화이력을 참조하여 완전한 문장으로 복원
- 복원된 문장으로 `classify_intent_v2` 재실행
- 예: "그거 정리해줘" -> "야근 수당 관련 규정을 문서로 정리해줘"

### clarify_with_candidates
- BERT confidence가 0.7 미만일 때 진입
- top-3 intent 후보를 버튼으로 사용자에게 제시
- 사용자가 버튼 클릭 -> 해당 내용으로 재질문 -> 정확한 Agent로 라우팅

### safe_*_agent (래퍼 패턴)
- 팀원 Agent가 `NotImplementedError` 던지면 "구현 중" 메시지로 대체
- `stream_mode=True`이면 Agent 호출 건너뛰고 `chat.py`에서 직접 LLM 스트리밍
- 래퍼: `safe_judgment_agent`, `safe_document_agent`, `safe_schedule_agent`

### format_response
- 모든 경로의 마지막 노드
- `agent_response`에 `type`/`message` 필드 보장 (안전장치)

## 설정값 (ai/agents/config.py)

| 설정 | 값 | 설명 |
|------|---|------|
| `INTENT_CONFIDENCE_THRESHOLD` | 0.7 | 이하면 clarify (top-3 후보 제시) |
| `INTENT_FALLBACK_THRESHOLD` | 0.5 | 이하면 general 강제 |
| `ENABLE_COMPLEX_QUERY` | False | 복합 질문 분해 (현재 비활성) |
| `CONTEXT_HISTORY_TURNS` | 5 | 맥락 해석 시 참조할 대화 턴 수 (x2 = 10개 메시지) |

## 지시어 감지 패턴 (intent_classifier.py)

```python
CONTEXT_DEPENDENT_PATTERNS = [
    r"(그거|그것|그걸|아까|위에|방금|이전에|앞에서|말한|언급한)",
    r"(그|이|저)\s*(문서|보고서|회의|규정|일정|내용)",
    r"(다시|한번 더|또)\s*(해줘|보여줘|알려줘)",
]
```

- BERT가 아닌 **정규식 패턴 매칭**으로 감지
- 감지되면 `resolve_context`로 라우팅 -> LLM이 복원 -> BERT 재분류

## 비활성 기능 (주석 처리)

### 복합 질문 분해
- `decompose_and_classify` -> `execute_sub_queries` -> `merge_responses`
- LLM이 복합 질문을 서브쿼리로 분해 -> 각각 Agent 실행 -> 결과 병합
- `ENABLE_COMPLEX_QUERY = True`로 변경 + 주석 해제 시 활성화

### post_execution_check
- Agent 실행 결과가 빈약할 때 다른 intent로 재분류 시도
