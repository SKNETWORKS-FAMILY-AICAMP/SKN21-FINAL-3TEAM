## 데이터 구조 요약

### v2_qa (문서 QA)
```json
{"messages": [
  {"role": "system", "content": "DOC_QA_SLLM_PROMPT"},
  {"role": "user", "content": "Context:\n[청크1, 청크2, ...]\n\nQuestion: 질문"},
  {"role": "assistant", "content": "{\"answer\": \"답변\", \"citations\": [{\"content\": \"근거 원문\"}]}"}
]}
```
- not-found 응답: `{"answer": "제공된 문서에서 해당 내용을 찾을 수 없습니다.", "citations": []}`
- not-found 비율: 12% (카테고리 교차 매칭으로 생성)

### v2_summary (문서 요약)
```json
{"messages": [
  {"role": "system", "content": "DOC_SUMMARY_SLLM_PROMPT"},
  {"role": "user", "content": "다음 문서를 요약해주세요.\n\n사용자 요청: 요약해줘\n\n문서 내용:\n원문"},
  {"role": "assistant", "content": "핵심 요약 문장\n\n## 주요 포인트\n- 포인트1\n- 포인트2\n- 포인트3\n\n## 키워드\n키워드1, 키워드2, 키워드3"}
]}
```

### v2_generate (문서 생성)
```json
{"messages": [
  {"role": "system", "content": "DOC_GENERATE_SLLM_PROMPT"},
  {"role": "user", "content": "[문서 유형] 회의록\n\n[필드 명세]\n- title: 설명\n- date: 설명\n...\n\n[회의 내용]\n원문"},
  {"role": "assistant", "content": "{\"title\": \"...\", \"date\": \"...\", ...}"}
]}
```
- 동적 필드: FIELD_POOLS에서 core(3) + meta(1~3) + content(2~4) = 6~10개 랜덤 조합
- 프로덕션에서는 템플릿 REQUIRED_FIELDS(8~10개)를 고정으로 전달

## 핵심 설계 결정

1. **프롬프트 v2**: 기존 LLM API 프롬프트와 별도로 sLLM 전용 프롬프트 설계 (간소화)
2. **동적 필드**: 고정 스키마 대신 필드 풀 랜덤 조합 → 어떤 필드 조합에도 대응 가능
3. **not-found 학습**: 카테고리 교차 매칭으로 "문서에 없는 질문" 12% 포함
4. **JSONL 포맷**: 한 줄 = 1건 → 중간 중단에도 데이터 유실 없음
5. **--append 패턴**: API 비용 절약을 위해 이어서 생성 가능하도록 설계
