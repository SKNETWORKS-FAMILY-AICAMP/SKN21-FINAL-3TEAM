# 문서 생성(v2_generate) sLLM 파인튜닝 요약

## 왜 sLLM?

GPT-4o API → 비용 + 보안 + 지연 → 자체 서버로 대체

## 모델 선정

8B급 한국어 모델 3개 비교 (동일 데이터/설정/eval)

| 모델 | JSON 유효율 | 결과 | 사유 |
|------|:-----------:|:----:|------|
| Qwen3-8B | 90.67% | 탈락 | Thinking Mode가 JSON 깨뜨림 |
| EXAONE-7.8B | 98.67% | 탈락 | 비상업적 라이선스 (서비스 배포 불가) |
| **Kanana-8B** | **98.67%** | **선택** | **loss 최저 + Apache 2.0** |

- **loss 최저** = 같은 데이터로 가장 잘 학습됨 (eval loss 0.7257)
- **Apache 2.0** = 상업적 사용 자유 (EXAONE은 서비스 배포 불가)
- **한국어 강점** = Kakao가 한국어 중심으로 사전학습

## 데이터

| 항목 | 값 |
|------|-----|
| 총 데이터 | 1,500건 (train 1,350 / eval 150) |
| 문서 유형 | 회의록 600 + 보고서 450 + 제안서 450 |
| 데이터 소스 | AI Hub 46% + GPT-4o/Claude 합성 40% + 변형 14% |
| 할루시네이션 방지 | 합성 중 30%를 부분 누락으로 생성 |

## 평가 방법

**정량 (자동)**: eval 150건으로 모델 출력 vs 정답 JSON 비교

| 지표 | 의미 |
|------|------|
| JSON 유효율 | 출력이 JSON으로 파싱 가능한가? |
| 필드 완성도 | 정답 키가 빠짐없이 다 있는가? (누락 체크) |
| 필드 정확도 | 키 이름이 정답과 똑같은가? (이름 체크) |

**정성 (수동)**: 샘플 비교 수준, 체계적 평가는 미완

## eval loss란?

- 모델이 처음 보는 150건에서 정답 토큰과 얼마나 다른지
- 낮을수록 좋음
- 절대 기준 없음, **"내려가다 올라가는 지점"**이 중요 (과적합 시작)

## 과적합 분석

| Epoch | Eval Loss | 비고 |
|:-----:|:---------:|------|
| 1 | 0.7406 | |
| 2 | **0.7257** | **최저 (best)** |
| 3 | 0.7312 | ← 과적합 시작 |
| 4 | 0.7448 | |
| 5 | 0.7569 | |

→ **epoch 3에서 과적합 시작** (eval loss 상승)
→ best model은 epoch 2 체크포인트

## Base vs Fine-tuned

| 지표 | Base (파인튜닝 전) | Fine-tuned |
|------|:------------------:|:----------:|
| JSON 유효율 | 100% | 98.67% |
| 필드 완성도 | 99.33% | 98.67% |
| 필드 정확도 | 100% | 100% |

⚠️ **숫자만 보면 base가 더 좋음**

- base는 Kakao가 이미 instruction following 학습시킨 모델이라 구조는 잘 만듦
- 파인튜닝 효과는 **"내용 품질"**에 있다고 주장 (할루시네이션 제거, 간결성)
- 단, 이걸 정량화한 평가는 아직 없음 **(숙제)**
