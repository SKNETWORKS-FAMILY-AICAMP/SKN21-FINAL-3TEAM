## 1. 문서 Agent 프로덕션 목표

문서 Agent는 4가지 기능을 수행하며, 이 중 3가지(generate/qa/summary)를 LoRA로 파인튜닝한다.

| 기능 | 입력 | 출력 | 핵심 학습 목표 |
|------|------|------|---------------|
| **doc_generate** | 사용자가 쓴 회의/업무 내용 | 7~15필드 **JSON** (회의록/보고서/제안서) | 정확한 필드명 + 구조화된 JSON 출력 |
| **doc_qa** | RAG 검색된 문서 청크 3~5개 + 질문 | **JSON** (answer + citations + confidence) | 인용 정확도 + 문서 기반 답변 |
| **doc_summary** | 문서 원문 | **마크다운** (핵심요약 + 주요포인트 + 키워드) | 구조화된 마크다운 요약 |
| doc_search | 사용자 질문 | 자연어 답변 | 파인튜닝 대상 아님 (RAG 품질이 핵심) |

### 프로덕션 출력 형식

**doc_generate (JSON)**:
```json
{
  "title": "회의 제목",
  "date": "YYYY-MM-DD",
  "attendees": ["참석자1", "참석자2"],
  "summary": "3~5문장 요약",
  "decisions": ["결정사항1"],
  "action_items": [{"content": "내용", "assignee": "담당자", "due_date": "YYYY-MM-DD"}],
  "risks": [{"description": "리스크", "level": "상/중/하", "regulation": ""}]
}
```

**doc_qa (JSON)**:
```json
{
  "answer": "답변 텍스트",
  "citations": [{"source": "문서명", "content": "인용 내용", "relevance": "높음|중간|낮음"}],
  "confidence": 0.0~1.0
}
```

**doc_summary (마크다운)**:
```markdown
핵심 요약 문장 (2~3문장)

## 주요 포인트
- 포인트 1
- 포인트 2

## 키워드
키워드1, 키워드2, 키워드3
```

### SN 582 데이터 구조

파일 1건 = JSON 1개 = passage 1건. 중첩 구조:

```json
{
  "Meta(Acqusition)": {
    "doc_id": "고유ID",
    "doc_category": "카테고리",
    "doc_type": "news_r|briefing|minute|...",
    "doc_name": "문서명"
  },
  "Meta(Refine)": {
    "passage": "원문 텍스트 (수백~수천 자)"
  },
  "Annotation": {
    "summary1": "한 줄 생성요약 (추상형)",
    "summary2": "2-3문장 추출요약 (원문 문장 복사)",
    "summary3": "20% 추출요약 (원문의 20% 분량)"
  }
}
```

> `2~3sent/` 폴더: summary1 + summary2 포함
> `20per/` 폴더: summary1 + summary3 포함
> **두 폴더의 passage는 서로 다른 문서** (동일 문서의 다른 요약이 아님)

### 요약 유형 특성

| 필드 | 유형 | 특성 | 예시 |
|------|------|------|------|
| summary1 | **생성형** (추상) | LLM이 새로 작성한 1문장 | "DH가 기업가치를 약 4조 8000억 원으로 평가한..." |
| summary2 | **추출형** | 원문에서 문장을 그대로 복사 | 원문의 특정 문장이 그대로 등장 |
| summary3 | **추출형** | 원문의 약 20%를 그대로 발췌 | 원문 핵심 문단을 그대로 나열 |

## 3. 카테고리별 실제 데이터 샘플

### news_r (뉴스)
```
passage: "40억 달러 '딜' 주인공 김봉진 우아한형제들 대표... 음식 배달 앱 '배달의민족'
         운영사의 서울 송파구 방이동 사옥은 비어 있었다..."
summary1: "DH가 기업가치를 약 4조 8000억 원으로 평가한 우아한형제들의 김 대표는
          국내 스타트업 사상 최대 규모의 M&A 이후 합작법인의 책임자가 된다."
```
→ 경제/기업 뉴스. 기업 업무 문맥과 자연스럽게 연결됨.

### briefing (보도자료)
```
passage: "5월은 양도소득세 확정신고납부의 달로 2020년에 부동산, 주식 등
         양도소득세 누진세율 대상 자산을 2회 이상 양도하고..."
summary1: "양도소득세 누진세율 대상 자산을 2회 이상 양도하고 소득 금액을
          합산신고하지 않았거나 국외 주식 거래에서 양도소득이 발생한 납세자는
          확정신고납부해야 한다."
```
→ 정부 정책/세무 안내. 보고서/제안서 생성의 소스로 적합.

### paper (간행물/보고서)
```
passage: "철저한 원가 분석을 통해 원가에 미달하는 가격규제로 인해 부채가 발생한
         부분과 그렇지 않는 부분을 구분하여 규명해야 함..."
summary1: "우리나라는 국가부채 통계를 1년에 딱 한 번 발표하므로 1년 동안
          어떻게 변화되어 왔는지 알 수 없지만..."
```
→ 정책 분석/예산 보고서. 업무 보고서와 가장 유사한 구조.

### minute (회의록 = 국회 속기록)
```
passage: '위원장 신학용] "수고하셨습니다. 다음은 존경하는 현영희 위원님
         인사말씀해 주세요."
         현영희 위원] "저는 부산 출신이고 비례대표 현영희입니다..."'
summary1: "아이들의 미래를 열어가는 장을 만들 수 있는 교과위에 오기를
          기대했던 박 위원은 아이들을 위한 일에 힘을 보태고 싶다고 말했다."
```
→ **국회 속기록**. `발언자명] "발언내용"` 형식. 기업 회의록과 스타일 불일치.

### speech (연설문)
```
passage: "고강도의 사회적 거리두기가 계속되면서 어려움을 느끼시는 분들이
         많으실 것입니다... 4차 유행의 차단을 위해 최대한 약속이나 모임,
         이동량을 줄여주시고..."
```
→ 정부 브리핑/연설. 요약 학습에 활용 가능.

### 업무 비적합 카테고리

| 카테고리 | 샘플 | 판단 |
|---------|------|------|
| his_cul | "국내에 남아있는 고려시대 종 가운데 가장 큰 종으로서..." | 업무 문서와 무관 |
| literature | "'나를 속일 리가 없을텐데... 알 수 있나? 열길 물속은 알아도...'" | 소설. 업무와 무관 |
| narration | "사실 경기 전망을 할 때 저희가 가장 먼저 보는 지표는 주식시장이죠." | 구어체 방송 대본 |

→ 이 3개는 **v2_summary에서만 소량 활용** (요약 능력 자체는 도메인 무관)

## 4. 어댑터별 적합성 판단

### v2_summary (700개 AI Hub + 200 합성 + 100 변형 = 1,000개) — 적합

**목표**: 어떤 문서든 받아서 마크다운 요약(핵심요약 + 주요포인트 + 키워드)을 생성

| 사용 카테고리 | 개수 | 적합 이유 |
|-------------|:----:|-----------|
| minute (회의록) | ~250 | 긴 텍스트 → 요약 학습에 최적. 국회 내용이라도 "요약" 자체는 도메인 무관 |
| paper + public (간행물) | ~250 | 보고서/정책 분석 → 기업 문서와 가장 유사한 구조 |
| news_r + briefing + edit | ~200 | 사실 기반 텍스트 → 요약 다양성 확보 |

**적합 근거**:
- 목표가 "요약 능력" 학습이므로 도메인보다 텍스트 다양성이 중요
- passage(원문) → 입력, summary2(추출형) → 요약의 seed로 활용
- summary2가 추출형이므로 GPT-4o mini로 마크다운 구조(`## 주요 포인트`, `## 키워드`)로 변환 필요

**주의점**:
- summary2는 원문 문장을 그대로 복사한 추출 요약
- AI Hub 70%로 제한 (80%→70%), 합성 20%로 추상형 모범답안 확보하여 추출형 편향 완화

---

### v2_generate report (210개 AI Hub) — 적합

**목표**: 사용자 입력 → 12필드 업무보고서 JSON

| 소스 카테고리 | 왜 적합한가 |
|-------------|-----------|
| paper (간행물) | 정책 분석, 예산 검토 내용 → "업무 보고서"와 동일한 구조 (개요→본문→과제→이슈) |
| briefing (보도자료) | 정부 정책 안내 → 보고 형식과 유사 (현황→조치→향후계획) |

**변환 방식**: passage → user input, GPT-4o → 12필드 JSON 생성
- paper의 `"철저한 원가 분석을 통해..."` → GPT-4o가 업무보고서 JSON으로 변환
- ~30%는 빈 필드 포함 (report_to, department 등)

---

### v2_generate proposal (210개 AI Hub) — 적합

**목표**: 사용자 입력 → 15+필드 제안서 JSON

| 소스 카테고리 | 왜 적합한가 |
|-------------|-----------|
| briefing (보도자료) | 사업/정책/예산 관련 → 제안서의 배경/목적/예산 필드에 매핑 |
| paper + public | 연구/정책 제안 → 제안서 구조와 유사 |

**변환 방식**: passage → user input, GPT-4o → 15필드 JSON 생성
- briefing의 `"양도소득세 확정신고납부..."` → "세무 시스템 개선 제안서" JSON으로 변환

---

### v2_generate meeting_minutes (40개 AI Hub) — 도메인 불일치, 합성 중심

**목표**: 사용자 입력 → 7필드 회의록 JSON

**문제**: AI Hub minute = 국회 속기록
- 형식: `위원장 신학용] "발언내용..."` (발언자 대화 형식)
- 기업 회의록: `"마케팅팀 주간회의, 참석자: 김민수 팀장..."` (서술형)
- 도메인: 국회 교육위원회 vs 기업 마케팅/개발/인사 회의
- **공개된 기업 회의록 데이터셋은 존재하지 않음** (기업 기밀)

**결정**: AI Hub 40개(다양성용) + GPT-4o/Claude 합성 280개(기업 도메인)

```
meeting_minutes 400개 구성:
├── GPT-4o/Claude 직접 합성: 280개 (70%)
│   └── 기업 도메인으로 직접 생성 (마케팅, 개발, 인사, 예산 회의 등)
├── 변형 (구어체/오타/불완전 입력): 80개 (20%)
└── AI Hub 국회회의록 변환: 40개 (10%) ← 소량만 다양성 확보용
```

---

### v2_qa (600개 AI Hub + 300 합성 + 100 변형 = 1,000개) — 적합

**목표**: 문서 청크 3~5개 + 질문 → JSON (answer + citations + confidence)

| 소스 | 개수 | 적합 이유 |
|------|:----:|-----------|
| SN 569 행정 문서 기계독해 | 300개 | 이미 MRC 형식(지문+질문+정답)으로 구성. 직접 변환 가능. 비용 $0 |
| SN 582 원문 기반 QA 생성 | 300개 | paper/briefing/news_r 원문 → 청크 분할 → GPT-4o가 QA쌍 생성 |

**적합 근거**:
- QA는 "문서에서 답을 찾는 능력"을 학습하므로 원문 도메인 영향이 적음
- 사실 기반 텍스트(보고서, 뉴스, 보도자료)는 명확한 답이 존재하여 QA쌍 생성에 최적
- SN 569는 이미 질문+정답 쌍이 있어 변환 효율이 높음
- 변형 10%로 제한하여 confidence 낮은 응답 편향 방지

## 5. 전체 판정 요약

| 어댑터 | 판정 | 사용 카테고리 | 비고 |
|--------|:----:|-------------|------|
| v2_summary (700개 AI Hub) | **적합** | 10개 전체 활용 가능 | summary2 → LLM 마크다운 변환 + 합성 20% 추상형 보강 |
| v2_generate report (210개 AI Hub) | **적합** | paper, briefing, public | GPT-4o → JSON 변환 |

### 최종 결론

**이 데이터로 파인튜닝 진행 가능.**

나머지 4개 영역(report, proposal, summary, qa)은 AI Hub 데이터가 목표에 적합하다.
