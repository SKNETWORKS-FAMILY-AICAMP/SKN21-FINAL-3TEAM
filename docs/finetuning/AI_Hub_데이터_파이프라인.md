# AI Hub 데이터 파이프라인 및 GPT-4o 활용 정리

## 1. AI Hub 022 데이터셋 개요

- **정식명**: 요약문 및 레포트 생성 데이터 (SN 582)
- **구조**: 각 JSON 파일 안에 `passage`(원문) + `summary`(요약)이 포함

### 폴더 구조

```
022.요약문 및 레포트 생성 데이터/
└── 01.데이터/
    ├── 1.Training/
    │   ├── 라벨링데이터/TL1/   ← 본문 + 요약 포함 JSON (실제 학습용)
    │   └── 원천데이터/TS1/     ← "원천데이터는 라벨링 데이터 파일 내 포함되어 있음"
    └── 2.Validation/
        ├── 라벨링데이터/VL1/   ← 검증용 (동일 구조)
        └── 원천데이터/VS1/     ← 마찬가지로 라벨링에 포함
```

### 2~3sent vs 20per

| 폴더 | 의미 | 설명 |
|------|------|------|
| **2~3sent** | 2~3문장 요약 | 원문을 2~3개 문장으로 압축 요약 (추상적 요약) |
| **20per** | 20% 비율 요약 | 원문 길이의 약 20% 분량으로 요약 (더 상세함) |

- `2~3sent` JSON: passage + summary1 + summary2
- `20per` JSON: passage + summary1 + summary3

## 1-B. AI Hub 016 데이터셋 개요

- **정식명**: 행정 문서 대상 기계독해 데이터

- **활용**: v2_qa 파이프라인에서 **SN 569** 로 참조 — GPT 없이 직접 QA 변환 가능

### 폴더 구조

### v2_qa에서의 활용 (SN 569로 참조)

- **사용 유형**: `span_extraction` + `span_extraction_how` (답이 본문에서 추출되는 자연스러운 QA)
- **GPT 불필요**: 이미 question + answer + context가 있어 형식 변환만 수행
- **변환 방식**: `context` → user의 Context 필드, `question` → Question 필드, `answer.text` → assistant의 answer
- **300건 사용**: v2_qa 전체 1,000건 중 AIHub MRC 직접 변환 300건

## 4. GPT-4o 개입 여부 정리

| 데이터 | GPT 사용 | 이유 |
|--------|:--------:|------|
| v2_summary AIHub (700건) | O | AI Hub 요약이 sLLM 프롬프트 형식(포인트+키워드)과 다르므로 GPT로 재생성 |
| v2_summary 합성 (300건) | O | GPT-4o가 원문+요약 모두 완전 합성 |
| v2_qa MRC (300건) | X | SN 569에 이미 question/answer가 있어서 형식 변환만 |
| v2_qa Report (300건) | O | SN 582에는 QA가 없으므로 GPT가 passage 보고 QA쌍 생성 |
| v2_qa 합성 (400건) | O | GPT-4o가 context+QA 모두 완전 합성 |
| v2_generate AIHub (700건) | O | SN 582에는 구조화 JSON이 없으므로 GPT가 passage -> JSON 변환 |
| v2_generate 합성 (800건) | O | GPT-4o가 시나리오+JSON 모두 완전 합성 |

**핵심**: AI Hub 원본에는 passage(원문)와 summary(요약)만 있고, sLLM이 배워야 할 형식(마크다운 요약, QA JSON, 구조화 JSON)은 원본에 없기 때문에 **GPT-4o를 "라벨러"로 써서 정답 데이터를 생성**하는 구조. 합성(synthetic) 데이터는 GPT-4o가 원문까지 포함해서 처음부터 만든 것.
