# LoRA v3 문서 요약 (v3_summary) 파인튜닝 결과

> v2 대비 변경: 출력 포맷 `분류:/태그:/요약:` 통일 + max_length 2560→8192 + 평가 방식 재설계

---

## 1. 개요

| 항목 | 내용 |
|------|------|
| **태스크** | 문서 요약 (Document Summary) |
| **목적** | 입력 문서 → `분류: / 태그: / 요약:` 구조화 출력 |
| **베이스 모델** | `kakaocorp/kanana-1.5-8b-instruct-2505` |
| **학습 방식** | QLoRA 4-bit (NF4) |
| **학습 일시** | 2026-03-17 |
| **학습 환경** | RunPod H200 141GB |

---

## 2. v2의 문제점

v2 summary LoRA는 학습은 됐으나 실서비스에서 쓸 수 없었음:

| 문제 | 상세 |
|------|------|
| **포맷 불일치** | 학습: `핵심요약/##주요포인트/##키워드` (마크다운) → 서빙: `분류:/태그:/요약:` (구조화) |
| **max_length 2560** | 전체 데이터의 51%가 truncation → 문서 끝부분을 못 보고 요약 |
| **평가 지표 부적합** | 분류 일치율, 태그 F1 등 표면 매칭 지표로 평가 → 실제 품질 반영 못함 |

---

## 3. v2 → v3 변경 사항

| 항목 | v2 (망한 버전) | v3 (이번) |
|------|---------------|-----------|
| 출력 포맷 | `핵심 요약 / ## 주요 포인트 / ## 키워드` | `분류: / 태그: / 요약:` |
| 시스템 프롬프트 | 마크다운 요약 전용 | `DOC_SUMMARY_SLLM_PROMPT` (서빙 동일) |
| max_length | 2,560 (51% truncation) | **8,192** |
| 분류 필드 | 없음 | 7종 (회의록/보고서/제안서/계약서/정책문서/인사문서/기타) |
| 태그 형식 | 쉼표 구분 키워드 | `#태그` 형식, 공백 제거 |
| 평가 방식 | 분류 일치율 + 태그 F1 + ROUGE-L | **BERTScore + 포맷 체크 + 정성 평가** |

## 7. 평가 방식 — 왜 summary는 다른 기준이 필요한가

### generate vs summary 평가의 차이

| | generate | summary |
|---|---|---|
| 출력 형태 | JSON (구조화) | 자연어 (요약문) |
| 정답 | 필드 있다/없다 (이진) | 같은 의미 다른 표현 가능 |
| 핵심 지표 | JSON 유효율, 필드 완성도 | **BERTScore (의미 유사도)** |
| 부적합 지표 | — | ROUGE-L (표면 매칭), 태그 F1 (동의어 불인정) |

### v2에서 잘못된 평가 (반면교사)

| 지표 | v2 결과 | 왜 부적합한가 |
|------|---------|-------------|
| 분류 일치율 36% | gold 분류가 규칙 기반이라 부정확, 사용자가 변경 가능 | 의미 없음 |
| 태그 F1 0.52 | `경주시` vs `경주` 표면 매칭 | 동의어 불인정 |
| ROUGE-L 0.31 | 같은 의미 다른 표현이면 낮음 | 품질 반영 못함 |

### v3 평가 기준 — 실서비스 관점

**정량 평가:**

| 지표 | 측정하는 것 | 근거 |
|------|-----------|------|
| 포맷 준수율 | `분류:/태그:/요약:` 3줄 구조 | 서빙 시 파싱 가능 여부 |
| 분류 유효율 | 7종 중 하나인지 | 사용자가 변경 가능하니 유효만 체크 |
| 태그 존재율 | 1개 이상 있는지 | 최소 기준 |
| 태그 적정(3~7) | ideal 범위 참고 | 서빙 후처리로 클리핑 가능 |
| 요약 길이 적정 | 20~500자 | 너무 짧거나 긴 거 필터 |
| **BERTScore F1** | 의미적 요약 품질 | **핵심 — 다른 표현도 인정** |
| ROUGE-L | 표면 단어 매칭 | 보조 참고만 |

**정성 평가:**

| 항목 | 방법 |
|------|------|
| 샘플 비교 | Gold vs Pred 5건 출력 (로그) |
| 전건 저장 | `qualitative_samples.json`에 100건 전부 → 수동 검토 |

## 9. Base vs Fine-tuned 비교

동일 eval 100건에 대해 Base 모델(LoRA 없음)과 Fine-tuned 모델을 비교했다.

### 9-1. 정량 비교

| 지표 | Base (LoRA 없음) | Fine-tuned (v3 LoRA) | 변화 |
|------|:----------------:|:--------------------:|:----:|
| 포맷 준수율 | 100% | **100%** | 동일 |
| 분류 유효율 | 85% | **100%** | **+15%p** |
| 태그 존재율 | 100% | **100%** | 동일 |
| 태그 적정(3~7) | 77% | **81%** | +4%p |
| 요약 길이 적정 | 98% | **100%** | +2%p |
| 평균 요약 길이 | 274자 | **132자** | FT가 2배 간결 |
| **BERTScore F1** | 0.8281 | **0.8594** | **+0.031** |
| ROUGE-L | 0.20 | **0.31** | **+0.11** |

### 9-2. 핵심 발견

**Base instruct 모델도 요약을 잘 한다** (BERTScore 0.83). 파인튜닝의 효과는 "dramatic한 성능 향상"이 아니라 **서비스 안정성 향상**:

1. **분류 유효율 85% → 100%** — Base는 "뉴스기사" 등 7종에 없는 카테고리 출력 (15건). FT는 항상 유효한 분류
2. **간결성 274자 → 132자** — Base는 장황, FT는 핵심만 간결하게
3. **BERTScore +0.031** — 의미적 품질 소폭 향상
4. **ROUGE-L +0.11** — 학습 데이터의 표현 패턴을 학습하여 일관된 출력

> **결론**: summary 태스크에서 파인튜닝은 "못하던 걸 되게 하는" 것이 아니라, "서비스 품질로 안정화"하는 효과. 분류 유효성 + 간결성 + 일관성이 핵심 개선점.

### 9-3. 참고 — 초기 Base 평가 파서 버그

초기 Base 평가에서 요약 0건으로 나왔으나, 이는 **파서 버그**였음:
- Base 모델은 `요약:` 뒤에 **개행 후 텍스트** 출력 (`요약:\n실제 텍스트`)
- 파서가 같은 줄만 읽어서 빈 문자열로 처리
- 멀티라인 파서로 수정 후 정상 결과 확인

### v4 실험: 성능 향상 시도 및 한계 확인

v3의 BERTScore(0.8594)를 올리기 위해 v4 실험을 진행했다.

**v4 변경 사항 (v3 대비):**

| 항목 | v3 | v4 | 변경 이유 |
|------|-----|-----|----------|
| LR | 1e-4 | **5e-5** | 과적합 방지, Base 요약 능력 보존 |
| epochs | 5 | **10** | LR 낮춰서 step 보상 |
| save_steps | epoch | **25** | 세분화 체크포인트로 최적점 탐색 |
| early_stopping | 3 | **5** | 느린 수렴 감안 |
| r / alpha | 16 / 32 | 16 / 32 | 유지 |

**v4 학습 결과:**
- Best checkpoint: step 250 (epoch 3.96), eval_loss = **0.9950** (v3: 0.9910)
- Early stopping patience=5 도달로 epoch 6.1에서 학습 종료
- LR 절반 × epoch 두 배 → v3과 동일 지점에 수렴

**v4 평가 결과 (v3 비교):**

| 지표 | v3 | v4 | 변화 |
|------|-----|-----|------|
| 포맷 준수율 | 100% | 100% | 동일 |
| 분류 유효율 | 100% | 100% | 동일 |
| 태그 적정(3~7) | 81% | **92%** | +11%p |
| 평균 태그 수 | 6.8 | 6.2 | 과다 생성 감소 |
| **BERTScore F1** | **0.8594** | 0.8573 | **-0.002 (소폭 하락)** |
| ROUGE-L | 0.3129 | 0.3052 | -0.008 |
| 평균 요약 길이 | 132자 | 139자 | 비슷 |

**결론: v3이 천장이다.**

- 핵심 지표(BERTScore, ROUGE-L) 모두 v4에서 소폭 하락 → v3 어댑터 유지
- LR을 바꿔도 같은 곳에 수렴 = **학습 방식이 아니라 데이터/모델이 병목**
- 8B 모델 + 900건 데이터 조합에서 BERTScore 0.86이 한계
- 태그 적정률(81%→92%)은 개선됐으나, 서빙 시 후처리 클리핑으로 동일하게 해결 가능
- 추가 실험(r=32, 다른 LR) 불필요 — 동일 데이터로는 더 이상 올라가지 않음
- 더 올리려면 **데이터 추가** 또는 **더 큰 모델**이 필요

**최종 판단: v3 어댑터 서빙 유지, v4 기각.**
