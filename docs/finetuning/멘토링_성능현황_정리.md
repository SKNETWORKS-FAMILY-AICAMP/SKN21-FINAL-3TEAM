## 멘토링 포인트

- **RAG 라이브 16.7% 문제**: Qdrant에 규정 문서가 제대로 적재되지 않았거나, eval 데이터의 컨텍스트와 실제 RAG 검색 결과 형식이 다를 가능성 → 현재 가장 큰 블로커
- **v1 > v2 교훈**: 데이터 양보다 **데이터 품질과 경계 케이스 설계**가 중요
- **RAG MRR 0.636→0.952**: 큰 성과 (평균 순위 2.65→1.0)
- **sLLM 전략**: LLM API로 먼저 전체 기능 구현 → 확정된 형태에 맞춰 파인튜닝 → vLLM 교체 (모델만 갈아끼우면 됨)
