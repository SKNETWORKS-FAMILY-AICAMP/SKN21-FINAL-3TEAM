# 문서생성 시연 가이드

## 기본템플릿 — 회의록

**폼 입력**
- 회의 제목: `CS팀 주간 정기회의`
- 날짜: `2026-03-29`
- 팀: `CS`

**회의 내용**
```
3월 28일 CS팀 주간 정기회의 진행. 참석자 김민수 팀장, 박지연 대리, 이준호 사원, 최수정 인턴. 고객 불만 접수 시스템 개선 논의. 현재 평균 응답시간 48시간에서 24시간 이내로 단축 목표 설정. AI 챗봇 도입 결정. 1차 배포 4월 15일 확정. 김민수가 4월 5일까지 AI 벤더 비교 보고서 작성. 박지연이 4월 10일까지 고객 FAQ 데이터 정리. 이준호가 4월 12일까지 챗봇 시나리오 설계. 최수정이 4월 8일까지 경쟁사 CS 벤치마크 조사. 월간 고객 만족도 조사 4월부터 시작 결정.
```

**검증 결과** (2026-03-29)
- 참석자 4명 정확 추출
- 결정사항 3건: AI 챗봇 도입, 4/15 배포, 만족도 조사
- 액션아이템 4건: 담당자 + 기한 정확 (김민수 4/5, 박지연 4/10, 이준호 4/12, 최수정 4/8)
- 할루시네이션 없음

## 기본템플릿 — 보고서

**폼 입력**
- 보고서 제목: `CS팀 3월 업무보고`
- 날짜: `2026-03-29`
- 팀: `CS`
- 작성자: `신지용`
- 보고 대상: `이사장`

**보고 내용**
```
CS팀 3월 업무보고. 고객 문의 처리 건수 1,250건 달성, 전월 대비 15% 증가. 평균 응답시간 36시간으로 전월 42시간 대비 개선. 고객 만족도 4.2점으로 목표 4.0 초과 달성. 챗봇 도입 검토 3월 10일 착수, 3개 벤더 후보 선정 완료. 신규 상담원 2명 3월 25일 채용 완료, 4월 1일 합류 예정. 이슈: 해외 고객 문의 증가로 영어 대응 인력 부족. 4월 계획: AI 챗봇 PoC 진행, 영어 상담 외주 검토, 상담 매뉴얼 개정.
```

**검증 결과** (2026-03-29)
- 수치 정확: 1,250건, 15%, 36시간, 4.2점
- 진행 업무: 챗봇 도입 (3/10 착수), 상담원 채용 (3/25 완료)
- 이슈/향후 계획 정확 반영
- 할루시네이션 없음

> **주의**: 날짜를 명시하지 않으면 sLLM이 종료일 등을 임의 생성할 수 있음. 날짜가 있는 항목은 입력에 명시할 것.

## 기본템플릿 — 제안서

**폼 입력**
- 제안서 제목: `AI 워크플로우 시스템 도입 제안`
- 제출일: `2026-03-29`
- 회사명: `듀듀 테크놀로지`
- 담당자: `신지용`
- 제출처: `경영지원본부`

**제안 내용**
```
사내 업무 자동화를 위한 AI 워크플로우 시스템 도입 제안. 현재 반복 업무에 월 평균 320시간 소요. 회의록 작성, 보고서 생성, 일정 관리 등 수작업 비중 높음. AI 에이전트 기반 자동화로 업무 시간 40% 절감 기대. 도입 비용 5천만원, 연간 운영비 1천만원. 1단계 4월~5월 시스템 설계 및 PoC. 2단계 6월~7월 파일럿 운영. 3단계 8월~9월 전사 확대. 기대효과: 연간 1억2천만원 인건비 절감, 문서 품질 균일화, 직원 만족도 향상.
```

**검증 결과** (2026-03-29)
- 목적/배경/현황분석: 입력 내용 기반 구조화
- 추진 일정 3건: PoC → 파일럿 → 전사확대 (4단계씩)
- 예산 2건: 도입 5000만원 + 운영 1000만원
- 기대 효과: 1억2천만원 절감, 품질 균일화, 만족도 향상
- 할루시네이션 없음

## 커스텀 템플릿 — 프로젝트 회의록

> 시연 시나리오: 기존 커스텀 템플릿 삭제 → "프로젝트 회의록.docx" 새로 업로드 → AI 작성 → 문서 생성

### 1단계: 템플릿 업로드
- 기존 `회의록 양식(doc)(2)` 삭제
- 같은 파일을 **"프로젝트 회의록"** 이름으로 업로드

### 2단계: 핵심 내용 입력
```
3월 24일 프로젝트 킥오프 회의. 참석자 김팀장, 이대리, 박사원, 최인턴, 정과장. REST API 방식 채택 결정. DB 스키마 이번주 확정 결정. 프론트엔드 React 통일 결정. 김팀장이 4월 1일까지 API 설계서 작성. 이대리가 4월 3일까지 DB 스키마 확정. 박사원이 4월 5일까지 프론트 와이어프레임. 최인턴이 4월 7일까지 테스트 케이스. 정과장이 4월 10일까지 인프라 구성도.
```

### 3단계: "AI 문서 작성" 클릭 → 필드 자동 채움 확인 → "문서 생성 (DOCX)" 클릭

**기대 출력 (결정사항 테이블)**

| 내용 | 진행일정 |
|---|---|
| REST API 방식 채택 | |
| DB 스키마 확정 | 이번주 |
| 프론트엔드 React 통일 | |
| 김팀장이 API 설계서 작성 | 4월 1일 |
| 이대리가 DB 스키마 확정 | 4월 3일 |
| 박사원이 프론트 와이어프레임 | 4월 5일 |
| 최인턴이 테스트 케이스 | 4월 7일 |
| 정과장이 인프라 구성도 | 4월 10일 |

**검증 결과** (2026-03-29)
- 원본 DOCX 양식 유지 (placeholder 방식)
- 진행일정: 내용에서 날짜 자동 추출 + 내용에서 날짜 제거 (중복 해소)
- 연도 보정: sLLM이 2023년 생성 시 → X월 Y일 형태로 변환

## 시연 순서

| 순서 | 템플릿 | 시연 포인트 |
|---|---|---|
| 1 | 기본 회의록 | 결정사항 + 액션아이템 자동 추출, Pipeline/Google Tasks 연동 |
| 2 | 기본 보고서 | 수치/이슈/계획 구조화 |
| 3 | 기본 제안서 | 일정 테이블 + 예산 테이블 자동 생성 |
| 4 | **커스텀 프로젝트 회의록** | Word 업로드 → AI 작성 → 원본 양식 DOCX 출력 |
