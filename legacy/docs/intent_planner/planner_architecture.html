Intent 분류 → Planner → Agent 실행 흐름

핵심 질문

Intent 분류 모델이 이미 있는데, 왜 Planner 모델이 따로 필요한가?

Intent 분류는 "뭘 해야 하나?"에 답하고 (라벨 집합),
Planner는 "어떤 순서로, 어떤 쿼리를 넘길까?"에 답한다.

Intent 분류 vs Planner

Intent 분류 Planner
답하는 질문 뭘 해야 하나? 어떤 순서로 해야 하나?
출력 라벨 집합
{doc_retrieve, judgment, doc_generate}		 실행 계획
순서 + 의존성 + sub-query
모델 klue/roberta-large
338M, ONNX INT8		 Kanana-1.5-8B
QLoRA, vLLM 서빙
결정하는 것 어떤 Agent가 필요한지 병렬/순차, 의존성,
각 Agent에 넘길 쿼리

단일 질문 vs 복합 질문

단일 "보고서 작성해줘"

→ Intent: doc_generate → 바로 실행. Planner 불필요

복합 "회의록 찾아서 분석하고 보고서 만들어줘"

Intent 분류 출력: {doc_retrieve, judgment, doc_generate} — 순서 없는 집합

? 뭘 먼저? → 문서 찾아야 분석 가능

? 동시에 해도 돼? → 찾기→분석은 순차, 보고서는 둘 다 끝난 후

? 각 Agent에 뭘 넘겨? → 원문 전체? 해당 부분만?

→ 이 결정을 Planner가 한다

실험 근거: Planner LoRA vs 규칙 기반

100건 Held-out 테스트 결과 (3/18)

카테고리 Planner LoRA 규칙 기반
단일 질문 97% 97%
병렬 92% 33%
복합 (3-step) 74% 0%
전체 78% 60%

병렬 33% = 12건 중 4건만 정답. 규칙이 병렬 가능한 걸 무조건 순차로 처리.
복합 0% = 19건 중 0건 정답. step 누락, 순서 오류, 의존성 잘못 설정.

한 줄 요약

Intent 분류는 "어떤 Agent가 필요한지"를 판별하고, Planner는 복합 질문일 때 "실행 순서 + 의존성 + 각 Agent에 넘길 sub-query"를 결정한다. 단일 질문에서는 Planner 없이 바로 Agent로 라우팅된다.
