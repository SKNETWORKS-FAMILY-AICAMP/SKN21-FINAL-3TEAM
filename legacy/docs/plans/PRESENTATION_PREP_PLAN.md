## 2. 추가/보강 제안

### 반드시 추가 (Must-Have)

#### A. 팀원 진승언 추가
- 팀 구성 섹션에 진승언(AI리드) 카드 추가
- 역할: AI 리드 (문서 Agent + 파서 + 템플릿)

#### B. 화면 구성 (Pages) 섹션 추가
- 실제 UI 스크린샷 or 목업 최소 4~5장
  - 채팅 화면 (규정 판단 예시)
  - 문서 생성 결과 화면
  - 캘린더/일정 화면
  - 대시보드
- 15분 발표에서 **"실제로 이렇게 동작합니다"**가 없으면 설득력 부족

#### C. 온프레미스 + 파인튜닝 차별화 슬라이드 (1장)
- **왜 sLLM인가?** → 보안(사내 데이터 외부 유출 차단), 비용(API 과금 탈피), 커스터마이징
- **Kanana-1.5-8B 선정 이유** → 한국어 벤치마크 최고, 8B라 A100 1장으로 서빙 가능
- **LoRA 핫스왑** → 하나의 base 모델에 4개 어댑터 (판단/생성/요약/플래너)
- **온프레미스 서빙 스택**: vLLM + RunPod A100 → EC2 자체 GPU로 전환 가능한 구조
- 이 슬라이드를 솔루션 바로 뒤에 배치하면 "우리가 뭘 다르게 했는가"를 초반에 각인시킬 수 있음

### 강력 권장 (Should-Have)

#### D. 데모 시나리오 준비
- **라이브 데모** or **녹화 영상** (2~3분)
- 추천 시나리오:
  1. "인턴에게 AWS 접근 권한 줘도 돼?" → 판단 Agent 응답
  2. "오늘 회의록 만들어줘" → 문서 생성 + DOCX 다운로드
  3. "내일 3시에 팀 미팅 잡아줘" → 일정 등록 + Google Calendar 반영

#### E. 개발 전략 슬라이드 (1장)
```
LLM API(GPT/Claude)로 전체 기능 먼저 구현
  ↓ (프로토타입 완성 + I/O 형태 확정)
데이터 수집 & 파인튜닝
  ↓ (LoRA 학습)
sLLM(vLLM) 교체 — 모델만 갈아끼우면 됨
```
- 이 접근이 왜 좋은가: 개발 속도 + 품질 보장 + 점진적 전환

### 있으면 좋음 (Nice-to-Have)

#### F. 프로젝트 수치 한눈에 요약 (1장)
- 코드 라인 수, 커밋 수, 이슈 수, PR 수 등
- "2개월간 5명이 이만큼 했다"는 규모감 전달

## 3. 프로젝트 잘한 점 분석 (강조 포인트)

발표에서 강조할 **핵심 차별점** 순위:

### 1위: 온프레미스 sLLM 파인튜닝 (4종 LoRA 어댑터)
- 부트캠프 수준에서 **4종 LoRA를 각각 파인튜닝하고 vLLM으로 서빙**한 것은 매우 드문 사례
- 판단 37.2% → 85.4%, 문서 생성 BERTScore 0.896 → 0.926 등 **수치로 증명**
- "GPT API 쓰면 되는데 왜?"에 대한 명확한 답: **보안 + 비용 + 커스터마이징**

### 2위: 체계적 실험 과정
- Intent: 규칙 → KoELECTRA → roberta-large + KD + 앙상블 (41.7% → 91.0%)
- 판단: 7회 실험으로 Base → v3 진화 과정을 추적
- **"결과만 보여주는 게 아니라, 왜 이 선택을 했는지"** 과정을 보여줄 수 있음

### 3위: 멀티 에이전트 아키텍처 (LangGraph)
- 단순 챗봇이 아닌 **Intent 분류 → 오케스트레이터 → 전문 Agent 라우팅**
- Task Planner로 복합 요청 자동 분해 (1-step 91.5%, 2-step 84.9%)

### 4위: RAG 파이프라인 고도화
- 단순 벡터 검색이 아닌 **BM25 + Vector + RRF + Reranker + HyDE**
- MRR 0.636 → 0.952 달성

### 5위: Google Workspace 5종 통합
- Calendar, Meet, Tasks, Gmail, Sheets — **실용적 가치** 어필
